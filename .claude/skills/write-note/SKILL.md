# Note 한 편 쓰기

Source 하나를 읽고 Note 한 편을 쓴다. 용어는 [CONTEXT.md](../../../CONTEXT.md)의 정의를 그대로 쓴다 — Source, Note, Take, Concept.

## 이 스킬이 하지 않는 것

[ADR-0004](../../../docs/adr/0004-the-skill-does-not-invent-the-perspective.md)가 이 스킬의 헌법이다.

- **관점을 지어내지 않는다.** "여기서 뭐가 새로웠나", "어디에 쓸 생각인가", "믿기지 않는 대목은"에 대한 답은 사람 것이다. 원문에서 그럴듯한 문장을 뽑아 그 자리를 채우면 Concept 그래프가 "내 관심의 궤적"이 아니라 "그럴듯하다고 판단된 것의 궤적"이 된다.
- **질문 단계를 건너뛰지 않는다.** 초안 생성은 한 번의 호출이 아니라 대화다. 느려 보이는 것은 비효율이 아니라 이 저장소가 성립하는 조건이다. 사람이 "알아서 써줘"라고 해도 질문은 던진다.
- **되물을 자리를 고쳐서 넘기지 않는다.** 게이트가 되묻자고 하면 초안을 보여주지 않는다. 반쯤 쓴 문장을 먼저 보여주면 사람이 고치는 대상이 백지가 아니라 기계가 쓴 문장이 되고, 그때부터 관점은 기계 것이다.
- **원문을 대신 요약하지 않는다.** 본문 대부분은 관점이고 원문의 주장은 짧게 가리키는 데 그친다 ([ADR-0003](../../../docs/adr/0003-note-does-not-replace-the-source.md)).
- **브리핑을 Note 본문으로 옮기지 않는다.** 3단계의 브리핑은 사람이 질문에 답하려고 읽는 것이라 길어도 되지만, 발행되는 것은 Note다. 인용·번역·관찰을 본문에 실어 나르면 ADR-0003이 조용히 뒤집힌다. 브리핑에서 Note로 넘어가는 것은 `sourceClaim` 세 문장뿐이다.

## 절차

### 1. 중복 Source를 먼저 본다

링크를 받으면 원문을 열기 전에 이미 쓴 Note인지 본다. Source가 Note의 식별자라서, 같은 URL로 두 편을 쓰면 한 원문이 Concept 그래프에서 두 번 센다.

```bash
node --input-type=module -e '
import { readRepository } from "./packages/core/src/repository/read.ts";
import { findDuplicateSource } from "./packages/core/src/note/duplicate.ts";

const source = process.argv[1];
const { notes, concepts } = await readRepository(process.cwd());
const duplicate = findDuplicateSource({ source, notes });

console.log(JSON.stringify({
  duplicate,
  vocabulary: concepts.map(({ concept }) => concept),
}, null, 2));
' "<링크>"
```

`duplicate`가 나오면 거기서 멈추고 사람에게 알린다 — 이미 쓴 Note의 경로와 제목을 보이고, 새로 쓸지 그 Note를 고칠지 묻는다. 임의로 진행하지 않는다.

`vocabulary`는 6단계에서 게이트에 넘길 기존 Concept 어휘다. 여기서 받아 들고 있는다.

### 2. Source를 통째로 가져온다

```bash
python3 .claude/skills/write-note/scripts/fetch_source.py "<링크>" --out /tmp/source
```

URL 유형을 스스로 가려 유튜브면 메타·설명·챕터·자막을, 블로그면 본문을, X면 글을 JSON 하나로 내놓는다. 자막과 본문 전문은 `--out` 디렉터리에 `transcript.txt` · `text.txt`로 떨어지므로 긴 것은 그 파일을 읽는다.

`WebFetch`를 먼저 쓰지 않는다. WebFetch는 작은 모델이 페이지를 읽고 질문에 답해 주는 도구라 돌아오는 것이 원문이 아니라 그 모델의 요약이고, 요약의 요약을 재료로 삼으면 사람이 "여기가 걸린다"고 짚을 대목이 이미 깎여 나간 뒤다. 스크립트가 `ok: false`를 내거나 유형을 못 잡는 자리에서만 WebFetch로 보완한다.

**`missing`을 반드시 읽는다.** 못 읽은 것이 여기 들어온다 — 자막 없는 영상, 280자에서 잘린 X 글, 로그인이 막은 본문. 이건 3단계 브리핑의 마지막 줄에 그대로 옮긴다. 조용히 넘기면 사람은 기계가 원문을 다 읽은 줄 알고 답하게 되고, 그 답으로 쓴 Note는 읽지도 않은 것에 대한 판단이 된다.

읽지 못한 것이 있어도 멈추지 않는다. 설명란과 챕터만으로도 원문이 무슨 말을 하려는지는 대개 잡히고, 무엇을 못 읽었는지 밝힌 채로 답하는 것은 사람이 할 수 있는 선택이다.

### 3. 한글 브리핑을 보인다

사람이 4단계의 질문에 답하려면 원문을 알아야 한다. 그 자리를 브리핑이 맡는다. **원문이 영어여도 브리핑은 한글로 쓴다.** 다만 `harness`, `context engineering`처럼 원문이 이름으로 쓰는 기술 용어는 옮기지 않고 그대로 둔다 — 번역해 두면 나중에 Concept 이름을 정할 때 원문과 이어 붙지 않는다.

**브리핑과 질문도 평서체로 쓴다.** 묻는 말투가 답하는 말투를 끌고 가서다. 경어체로 물으면 경어체로 답이 오고, 그 답이 그대로 `harvest`·`application`·`doubt`가 되어 6단계 게이트가 경어체를 고치게 되는데, 게이트는 세 자리에서 틀리게 고친다. 평서체로 물으면 그 교정이 애초에 필요 없다.

다섯 자리로 짠다.

```
**Source** — [{제목}]({링크}) ({채널·글쓴이}, {길이 또는 분량})

**원문의 주장** — {세 문장 이내}

### 원문에서

> {영어 원문 그대로}

{한글 번역}

### 눈에 걸린 자리

- {원문 안에서 확인되는 것}

*못 읽은 것 — {missing}*
```

마지막 두 절은 내용이 없으면 통째로 뺀다. `missing`이 비었으면 그 줄도 없다.

**원문의 주장**만 세 문장으로 묶는 이유가 있다. 브리핑 전체는 대화에서만 살고 사라지지만 이 세 문장은 Note 본문으로 넘어가므로, 여기서부터 ADR-0003의 분량을 지킨다. 인용도 관찰도 Note에는 안 들어간다.

**원문에서**는 영상이나 글이 실제로 뭐라고 말했는지를 원문 그대로 한두 대목 보이는 자리다. 요약만 읽으면 사람은 내 번역을 통과한 문장에 대해 답하게 되는데, 뉘앙스가 걸리는 곳은 대개 그 통과 과정에서 사라진다. 길게 뽑지 않는다 — 두세 문장짜리 대목 하나나 둘이면 된다.

`transcript_kind`가 `auto`면 자동 자막이다. 인용하기 전에 아래 "자동 자막은 이름을 틀린다"를 본다.

#### 눈에 걸린 자리에 쓸 수 있는 것

[ADR-0005](../../../docs/adr/0005-the-observer-uses-only-observable-verbs.md)가 Portrait에 건 규칙을 여기에 그대로 쓴다. **관찰은 되고 해석은 안 된다.** 판정의 범위는 원문 안의 사실과 사실끼리의 대비까지다.

| | |
|---|---|
| **쓴다** | "챕터 제목은 `Limits`인데 그 구간에서 든 사례는 하나다" · "앞에서 A라고 한 것을 뒤에서 B라고 한다" · "이 주장의 근거로 든 것이 스폰서 제품이다" · "8분 중 1분 13초가 광고다" · "X를 여러 번 말하는데 정의는 안 한다" |
| **안 쓴다** | "이 대목이 핵심이다" · "여기가 새롭다" · "이건 의심스럽다" · "설득력이 약하다" · "지금 하는 작업에 쓸 만하다" |

오른쪽 칸은 전부 4단계 질문의 답이다. 기계가 먼저 말해 버리면 사람은 백지에 답하는 대신 내가 쓴 문장을 고치는 사람이 되고, 그때부터 Concept 그래프는 관심의 궤적이 아니라 그럴듯하다고 판단된 것의 궤적이 된다 (ADR-0004). 왼쪽 칸은 다르다 — 원문을 다시 안 봐도 확인되는 사실이라, 사람이 판단할 재료지 판단 자체가 아니다.

짚을 것이 없으면 이 절을 통째로 뺀다. 채우려고 억지로 찾으면 관찰이 아니라 트집이 되고, 트집은 오른쪽 칸이다.

### 4. 질문을 던진다

세 질문을 한 번에 던지고 답을 기다린다.

1. **여기서 뭐가 새로웠나** — 이미 알고 있던 것과 어디가 달랐나
2. **어디에 쓸 생각인가** — 지금 붙잡고 있는 코드나 결정 중 어디에 닿나
3. **믿기지 않는 대목은** — 원문이 너무 쉽게 넘어갔다고 느낀 곳이 어디였나

브리핑에서 얻은 맥락으로 질문을 이 Source에 맞게 구체화해도 된다. 질문의 수를 줄이거나 답을 예시로 채워 보이는 것은 안 된다 — 예시가 곧 답이 된다. 3단계에서 짚은 관찰을 질문에 얹는 것도 여기까지다. "여기가 걸리지 않나"는 이미 답이다.

답을 받으면 **Take 한 문장**을 사람의 답에서 뽑아 확인받는다. Take는 원문의 주장이 아니라 내 수확이다.

### 5. 초안 재료를 모은다

`NoteDraft` 한 덩어리로 모은다.

| 자리 | 어디서 오나 |
|---|---|
| `source` | 1단계에서 받은 링크 |
| `title` | 원문이 던진 질문 형태로 짓는다. 사람에게 확인받는다 |
| `date` | 오늘 (`YYYY-MM-DD`) |
| `take` | 4단계에서 확인받은 한 문장 |
| `concepts` | 이 Note가 다루는 Concept. 1단계의 `vocabulary`를 먼저 보고 이미 있는 이름이면 그것을 쓴다 |
| `sourceClaim` | 3단계 브리핑의 **원문의 주장** 세 문장. 브리핑의 다른 자리는 가져오지 않는다 |
| `harvest` | 질문 1의 답 |
| `application` | 질문 2의 답 |
| `doubt` | 질문 3의 답 |

`harvest` · `application` · `doubt`는 사람의 답을 그대로 옮긴다. 문장을 다듬는 것은 7단계에서 하고, 여기서는 내용을 보태지 않는다.

### 6. 게이트에 넣는다

```bash
node --input-type=module -e '
import { judgeDraft } from "./packages/core/src/note/rubric.ts";

const { draft, vocabulary } = JSON.parse(process.argv[1]);

console.log(JSON.stringify(judgeDraft({ draft, vocabulary }), null, 2));
' "$(cat /tmp/draft.json)"
```

판정은 두 갈래고, 갈래마다 할 일이 다르다.

**`outcome: "ask-back"`** — 재료가 모자란다. `corrected`가 아예 없다.

- `askBack[].question`을 사람에게 그대로 던진다. 답을 다시 받아 5단계로 돌아간다.
- **초안을 보여주지 않는다.** 조립한 문장도, 고칠 수 있었던 형식도 꺼내지 않는다.
- 답을 대신 채우거나 문턱을 넘길 만큼만 늘려 쓰지 않는다.
- `field`가 `concepts`면 게이트가 이름을 하나도 확정하지 못한 것이다. `vocabulary`를 보고 **영어 이름을 정해** 5단계로 돌아간다. 기존 어휘에 뜻이 같은 것이 있으면 새 이름을 만들지 말고 그것을 쓴다 ([ADR-0001](../../../docs/adr/0001-note-connects-through-concept.md)). 이름이 관점을 담는 자리이므로 사람에게 확인받는다.
- 게이트의 판정이 틀렸다고 보이면 — 짧지만 날카로운 답이 걸렸다면 — 사람에게 그렇게 말하고 판단을 받는다. 게이트를 우회하는 것도 사람의 결정이다.

**`outcome: "pass"`** — `corrected`를 쓰고 `corrections`는 한 줄로 알린다.

- 경어체 교정과 Concept slug 교정은 되묻지 않고 이미 반영돼 있다. 무엇을 고쳤는지는 알리되 승인을 구하지 않는다.
- `after`가 `null`인 `corrections` 항목은 게이트가 이름을 확정하지 못하고 지운 Concept이다. 한글이 섞였거나(`React 서버 컴포넌트`) 영숫자로 옮길 수 없는 기호가 있는(`c++`) 이름이다. **게이트는 이런 이름을 깎아 내지 않는다** — `react`나 `c`로 줄이면 뜻이 다른 Concept이 조용히 굳기 때문이다. 지워진 자리마다 `vocabulary`를 보고 영어 이름을 정해 `concepts`에 다시 넣고 게이트를 다시 돌린다. 살아남은 이름이 하나도 없으면 애초에 `pass`가 나오지 않는다.
- **`corrections`의 `after`를 그대로 믿지 마라.** 아래 "경어체 교정이 틀리는 자리"를 보고, 걸리는 문장은 7단계에서 손으로 맞춘다.

#### 경어체 교정이 틀리는 자리

게이트는 동사와 형용사를 사전 없이 가르지 못한다. 그래서 **못 고치는 것보다 틀리게 고치는 것이 위험하다** — 경어체는 사라졌는데 어색한 문장만 남아 눈에 덜 띈다. 아래 세 유형은 `corrections`에 `after`가 들어와 있어도 다시 봐야 한다.

| 유형 | 들어온 것 | 게이트가 내놓는 것 | 맞는 것 |
|---|---|---|---|
| 받침 있는 동사 + `-습니다` | `바로 닿습니다` | `바로 닿다` | `바로 닿는다` |
| 어간이 `이`로 끝나는 동사 + `-입니다` | `분명히 보입니다` | `분명히 보이다` | `분명히 보인다` |
| `-지 않습니다`의 앞이 동사 | `말하지 않습니다` | `말하지 않다` | `말하지 않는다` |

같은 규칙이 아래에서는 맞게 돈다. 고쳐 놓고 또 고치지 마라.

| 들어온 것 | 나오는 것 |
|---|---|
| 과거형 — `나왔습니다`, `가까웠습니다` | `나왔다`, `가까웠다` |
| 받침 있는 형용사 — `가깝습니다`, `좋습니다` | `가깝다`, `좋다` |
| 명사 뒤 서술격 — `문제입니다`, `중간 계층입니다` | `문제이다`, `중간 계층이다` |
| `-하다` 형용사 — `중요합니다`, `필요합니다` | `중요하다`, `필요하다` |

`입니다`를 늦게 처리해 `보입니다`를 살리면 훨씬 흔한 `문제입니다`가 `문제인다`라는 비문이 된다. 표기가 같아 값싸게 가를 방법이 없어서 흔한 쪽을 살린 선택이고, 남은 자리를 여기서 사람이 본다.

손대지 못하는 경어체도 있다 — `-네요`, `-거든요`, `-지요`. 이건 `corrections`에 나타나지 않으니 원문 답변을 직접 훑는다.

### 7. 본문을 조립한다

`corrected`의 재료로 본문을 쓴다. 형식은 [notes/2026-07-08-parameter-object-pattern-js.md](../../../notes/2026-07-08-parameter-object-pattern-js.md)를 따른다.

```
{sourceClaim — 원문이 무슨 말을 하는지. 한 문단, 짧게}

{harvest — 내가 건진 것. 원문의 결론이 아니라 내 수확이 무엇인지}

## 어디에 쓸 생각인가

{application}

## 미심쩍은 대목

{doubt}
```

- 평서체 1인칭이다. "~라고 본다", "내가 건진 것은".
- 6단계의 표에 걸린 문장을 여기서 맞춘다. `닿다` → `닿는다`, `보이다` → `보인다`.
- 관점 문단에 사람이 말하지 않은 근거·사례·수치를 보태지 않는다. 문장을 잇고 다듬는 데까지다.
- 관련 Note로 가는 링크를 넣지 않는다. 관련성은 Concept을 거쳐 렌더링 시점에 계산한다 (ADR-0001).

### 8. 파일로 쓴다

경로는 `notes/{date}-{slug}.md`다. `slug`는 제목에서 사람이 알아볼 만한 영문 소문자 몇 단어로 줄인다 (`2026-07-08-parameter-object-pattern-js.md`).

```bash
node --input-type=module -e '
import { noteFrontmatterSchema } from "./packages/core/src/note/schema.ts";
import { renderMarkdown, writeMarkdown } from "./packages/core/src/repository/write.ts";

const { draft, body, path } = JSON.parse(process.argv[1]);
const { source, title, date, take, concepts } = draft;
const frontmatter = noteFrontmatterSchema.parse({ source, title, date, take, concepts });

const outcome = await writeMarkdown({
  root: process.cwd(),
  path,
  contents: renderMarkdown({ frontmatter, body }),
});

console.log(JSON.stringify(outcome));
' "$(cat /tmp/note.json)"
```

- `fs.writeFile`을 직접 부르지 않는다. 저장소에 파일을 쓰는 이음매는 `writeMarkdown` 하나다.
- `noteFrontmatterSchema.parse`가 던지면 그건 게이트를 통과했어도 형식이 어긋났다는 뜻이다. 메시지를 보고 고쳐 다시 돌린다.
- `{ kept: ... }`가 나오면 그 경로에 파일이 이미 있어 손대지 않은 것이다. 덮어쓰지 말고 사람에게 알린다.

### 9. 마무리

쓴 경로, 확정된 Concept, 게이트가 고친 것을 한 번에 보인다. `pnpm concepts`로 이 Note가 어떤 Concept을 3회에 가깝게 밀어 올렸는지 볼 수 있다 ([ADR-0002](../../../docs/adr/0002-concept-promotion-at-three.md)).

커밋은 하지 않는다. 발행 전에 사람이 문장을 고친다.

## 게이트가 판정하는 것과 못 하는 것

게이트(`packages/core/src/note/rubric.ts`)는 순수 함수다. 저장소를 읽지 않고, 넘겨받은 재료와 어휘만 본다.

확정적으로 판정하는 것 — Concept slug 형식, 기존 어휘와의 대조.

반쯤만 확정적인 것 — 경어체 교정. 검출은 확정적이지만 교정은 동사·형용사 구분에서 갈려 틀리게 고치는 자리가 남는다. 6단계의 표를 보고 사람이 마지막을 본다.

근사로 판정하는 것 — "관점이 얇다"는 글자 수로, "Take가 원문 요약이다"는 원문 요약과의 어휘 겹침으로 재는 기계적 근사다. 짧고 날카로운 답을 되묻게 만들 수 있고, 길게 늘여 쓴 빈 말은 통과시킨다. 애매하면 되묻는 쪽으로 기울여 있으며, 최종 판단은 이 대화에서 사람과 에이전트가 한다.

게이트를 자동 교정 쪽으로 옮기고 싶어질 때가 온다. 그건 개선이 아니라 ADR-0004의 철회다.

## 스크립트가 가져오지 못하는 것

`scripts/fetch_source.py`는 공개된 것만 가져온다. 페이월과 로그인은 뚫지 않는다. 못 가져온 것은 `missing`과 `diagnostics`에 남으므로, 이 두 자리를 안 읽으면 없는 것을 있다고 여기게 된다.

### 자동 자막은 이름을 틀린다

`transcript_kind`가 `auto`인 자막은 음성 인식 결과다. 문장 부호가 없고 **고유명사를 특히 자주 틀린다.** 한 영상에서 실제로 이런 것들이 걸렸다 — `Kayla Bright's Code`(채널명 Caleb Writes Code), `Klein`(Cline), `Raw`(Ralph), `WinServe`(Windsurf), `Rue`(Roo).

그대로 인용하면 원문이 하지 않은 말이 브리핑에 실린다. Concept 이름을 여기서 뽑으면 `raw`나 `klein` 같은 것이 저장소 어휘에 굳는다.

**이 목록을 사전으로 쓰지 마라.** 다른 영상의 `Raw`는 Ralph가 아니다. 이건 "이런 식으로 틀린다"는 예시이지 대응표가 아니고, 이름은 매번 그 Source 안에서 대조해 확인한다.

다행히 **교차 검증이 값싸다.** 같은 JSON 안의 다른 자리들은 자막과 독립적으로 얻어진 것이라서다. 자막을 뺀 나머지는 전부 글쓴이가 직접 타이핑한 글자다.

| 대조할 자리 | 무엇을 잡나 |
|---|---|
| `meta.author` | 채널명 정본. 자막이 부르는 채널 이름과 다르면 자막이 틀린 것이다 |
| `meta.keywords` | 글쓴이가 단 태그. 제품·도구 이름이 여기 자주 박힌다 — 위의 `Raw`·`Klein`·`WinServe`는 태그에 `ralph agent`·`cline agent`·`windsurf agent`로 적혀 있었다 |
| `description` · `chapters` | 본문과 챕터 제목에 적힌 표기 |
| 자막 자신 | 한 이름을 두 가지로 적기도 한다. 위 자막은 같은 도구를 `Klein`과 `Cline`으로 번갈아 적었다 |

네 자리를 다 보고도 대조할 것이 없으면, 고쳐 적지 말고 자막 표기 그대로 두고 확실하지 않다고 밝힌다. 짐작해서 고친 이름은 틀려도 티가 안 난다.

### 유형별로 못 가져오는 것

| Source | 가져오는 것 | 못 가져오는 것 |
|---|---|---|
| 유튜브 | 메타·설명·챕터·자막 | 댓글(일부러 안 받는다 — 수백 개를 긁는 데 몇 분이 걸리고 브리핑에 들어갈 값이 거의 없다) |
| X | 글 전문(280자를 넘겨도), 인용된 글의 본문 | 뒤로 이어지는 답글. 이 글이 스레드 중간이면 앞글 |
| 블로그 | 본문 | 로그인·페이월 뒤의 것 |

X는 `fxtwitter`를 먼저 두드리고 실패하면 X의 syndication으로 물러선다. **`source_via`가 `syndication`이면 280자에서 잘렸는지 의심한다** — 그 경로는 긴 글의 뒷부분을 주지 않고 `missing`에 잘렸다고만 적는다. 두 경로의 차이가 작지 않다. 이 스킬을 만들며 같은 글을 syndication은 277자, `fxtwitter`는 1,375자로 줬다.

`missing`에 앞글이나 답글이 잡히면 사람에게 붙여 달라고 청하거나, 그 Source로는 못 쓴다고 말한다. 스레드의 한 토막만 읽고 전체에 대해 답하게 두면 원문에 없는 주장에 대한 Note가 나온다.
