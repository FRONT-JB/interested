# 감사 단계 eval

`study-source`의 4-2단계 감사를 재는 스위트다. 오독을 일부러 심은 브리핑을 `study-source-auditor`에 그대로 물려, **심은 것을 잡는지**와 **멀쩡한 자리를 걸지 않는지**를 본다.

여기만 재는 이유는 감사가 이 스킬의 유일한 비결정적 안전장치라서다. 인용·시각·링크는 `audit_briefing.mjs`가 결정적으로 잡고 그 회귀는 `briefing.test.ts`가 지킨다. 게이트도 `rubric.test.ts`가 지킨다. 감사만 모델이 진다.

## 돌리기

```bash
node .claude/skills/study-source/evals/run.mjs
node .claude/skills/study-source/evals/run.mjs --case inverted --case clean
```

토큰을 쓰므로 `pnpm test`에 붙이지 않는다. 모델이나 에이전트 정의를 바꿀 때 손으로 돌린다.

케이스마다 호출이 둘이다 — 감사 한 번, 채점 한 번. 채점기는 감사 결과가 자유 서술이라 문자열 대조로 셀 수 없어서 두었고, `--judge-model`로 바꿀 수 있다.

## 케이스

| 이름 | 심은 것 |
|---|---|
| `clean` | 없다. 여기서 무엇이든 걸리면 오탐이다 |
| `overstated` | 원문이 단 조건절을 떼고 단언으로 바꿨다 |
| `fabricated-number` | 원문이 "수치가 없다"고 한 자리에 수치를 넣었다 |
| `inverted` | 원문이 A가 아니라 B였다고 한 것을 뒤집었다 |
| `outline-title` | 덩어리 **본문**은 맞고 **제목**만 원문에 없는 단정을 담았다 |

마지막 케이스는 실제로 놓친 적이 있는 자리라 에이전트 정의에도 적혀 있다. 본문만 대조하는 감사자는 여기서 걸린다.

`clean`이 있는 것이 이 스위트의 절반이다. 잡는 것만 재면 "다 의심스럽다"고 답하는 감사자가 만점을 받고, 그런 감사자는 멀쩡한 문장을 브리핑에서 깎아 낸다.

## 원문 픽스처

`sources/` 아래 둘 다 이 저장소에서 직접 쓴 합성 글이다. 실제 원문의 자막이나 본문을 넣지 않는 이유는 저작권이고, 그건 [ADR-0003](../../../../docs/adr/0003-note-does-not-replace-the-source.md)이 Note에 건 제약과 같은 이유다.

## 케이스를 더할 때

`cases.json`에 항목을 넣고 `briefings/`에 브리핑을 둔다. 심은 오류마다 `anchor`는 **브리핑에 실제로 있는 표현 그대로**여야 한다 — 채점기가 그것으로 감사 결과를 대조한다.

한 케이스에 오류를 여럿 심을 때는 서로 다른 종류로 심는다. 같은 종류를 둘 심으면 잡는 수만 늘고 무엇을 못 잡는지는 안 드러난다.
