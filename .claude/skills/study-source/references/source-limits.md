# 스크립트가 가져오지 못하는 것

`scripts/fetch_source.py`는 공개된 것만 가져온다. 페이월과 로그인은 뚫지 않는다. 못 가져온 것은 `missing`과 `diagnostics`에 남으므로, 이 두 자리를 안 읽으면 없는 것을 있다고 여기게 된다.

## 자동 자막은 이름을 틀린다

`transcript_kind`가 `auto`인 자막은 음성 인식 결과다. 문장 부호가 없고 **고유명사를 특히 자주 틀린다.** 한 영상에서 실제로 이런 것들이 걸렸다 — `Kayla Bright's Code`(채널명 Caleb Writes Code), `Klein`(Cline), `Raw`(Ralph), `WinServe`(Windsurf), `Rue`(Roo).

그대로 인용하면 원문이 하지 않은 말이 브리핑에 실린다. Concept 이름을 여기서 뽑으면 `raw`나 `klein` 같은 것이 저장소 어휘에 굳는다. 틀린 이름을 검색어로 쓰면 조사 결과가 통째로 다른 것에 대한 설명이 된다.

**이 목록을 사전으로 쓰지 마라.** 다른 영상의 `Raw`는 Ralph가 아니다. 이건 "이런 식으로 틀린다"는 예시이지 대응표가 아니고, 이름은 매번 그 Source 안에서 대조해 확인한다.

다행히 **교차 검증이 값싸다.** 같은 JSON 안의 다른 자리들은 자막과 독립적으로 얻어진 것이라서다. 자막을 뺀 나머지는 전부 글쓴이가 직접 타이핑한 글자다.

| 대조할 자리 | 무엇을 잡나 |
|---|---|
| `meta.author` | 채널명 정본. 자막이 부르는 채널 이름과 다르면 자막이 틀린 것이다 |
| `meta.keywords` | 글쓴이가 단 태그. 제품·도구 이름이 여기 자주 박힌다 — 위의 `Raw`·`Klein`·`WinServe`는 태그에 `ralph agent`·`cline agent`·`windsurf agent`로 적혀 있었다 |
| `description` · `chapters` | 본문과 챕터 제목에 적힌 표기 |
| 자막 자신 | 한 이름을 두 가지로 적기도 한다. 위 자막은 같은 도구를 `Klein`과 `Cline`으로 번갈아 적었다 |

네 자리를 다 보고도 대조할 것이 없으면, 고쳐 적지 말고 자막 표기 그대로 두고 "확인 못 한 것"에 올린다. 짐작해서 고친 이름은 틀려도 티가 안 난다.

## 유형별로 못 가져오는 것

| Source | 가져오는 것 | 못 가져오는 것 |
|---|---|---|
| 유튜브 | 메타·설명·챕터·자막 | 댓글(일부러 안 받는다 — 수백 개를 긁는 데 몇 분이 걸리고 브리핑에 들어갈 값이 거의 없다) |
| X | 글 전문(280자를 넘겨도), 인용된 글의 본문 | 뒤로 이어지는 답글. 이 글이 스레드 중간이면 앞글 |
| 블로그 | 본문 | 로그인·페이월 뒤의 것 |

X는 `fxtwitter`를 먼저 두드리고 실패하면 X의 syndication으로 물러선다. **`source_via`가 `syndication`이면 280자에서 잘렸는지 의심한다** — 그 경로는 긴 글의 뒷부분을 주지 않고 `missing`에 잘렸다고만 적는다. 두 경로의 차이가 작지 않다. 이 스킬을 만들며 같은 글을 syndication은 277자, `fxtwitter`는 1,375자로 줬다.

`missing`에 앞글이나 답글이 잡히면 사람에게 붙여 달라고 청하거나, 그 Source로는 못 쓴다고 말한다. 스레드의 한 토막만 읽고 전체에 대해 답하게 두면 원문에 없는 주장에 대한 Note가 나온다.

## 자막이 아예 없으면

`missing`에 자막 없음이 잡히면 `원문이 한 말`을 설명란과 챕터만으로 지어야 한다. 그때는 덩어리를 억지로 5~7개로 맞추지 말고, 챕터가 알려주는 만큼만 적고 **"자막이 없어 챕터 제목과 설명란만으로 지은 것"이라고 브리핑에 밝힌다.** 인용 절은 통째로 뺀다 — 대조할 원본이 없으므로 4-3의 검사도 전부 걸린다.
