다듬지 않은 생각을 음성 받아쓰기로 markdown 폴더에 최대한 많이 쌓아 두는 것이 LLM 지식 베이스의 출발점이다. 그 원재료에 태그·출처·백링크를 붙이고 그 위에 위키와 그래프 뷰를 얹는 일은 사람이 손으로 하지 않고 에이전트 스킬이 한다. 그 스킬을 클라우드 샌드박스에서 매일 돌리면 아침마다 갱신된 지식 베이스를 받는다.

## 원문이 한 말

흩어진 메모 더미를 돌아다닐 수 있는 것으로 바꾸는 것이 목표이고, 노트는 markdown으로 두어 아무 뷰어로나 본다. 생각을 옮기는 가장 빠른 방법은 음성 받아쓰기이고 평균 분당 200단어쯤 되며, 구독 없이 로컬 모델로 도는 도구가 있다. 형식 없이 산만하게라도 원재료를 많이 쌓아 두고, 태그·출처·보강 시각·백링크는 enrich note 스킬이 나중에 붙인다. 태그는 preference 폴더의 목록에서 고르게 해 에이전트가 매번 새 이름을 지어내지 않게 하되, 패턴이 뚜렷하면 목록에 더해도 된다고 지시한다.

보강된 노트 위에 위키를 생성시키면 출처·개념·사람·조직 항목이 나오고, 이 발상의 출처는 Andrej Karpathy의 gist다. 이 작업이 시간을 먹으니 클라우드 샌드박스가 markdown 폴더를 내려받아 스킬을 돌리고 다시 올리는 구조로 매일 자동으로 돌린다. 마지막으로 노트 전체를 HTML 그래프 뷰로 그리게 해, 무엇에 관심이 있고 어디가 비어 있는지 한눈에 본다.

## 내가 건진 것

다듬지 않은 생각을 그냥 넣어두고 나중에 가공하는 순서가 새로웠다. 나였으면 처음부터 가공하는 방식을 채용했을 텐데, 실제로 그렇게 했다가 걸린 적이 있다. 처음부터 frontmatter를 과도하게 설정해서 불필요한 필드값이 많아진 경우다. 미리 가공해 두니 다른 파편화된 데이터를 접목시킬 때마다 필드값이 부족하거나 과한 경우가 생겼다. 파편화된 정보들을 수집해서 가공하려면 후처리를 통해서 처리하는 게 좋아 보인다.

## 어디에 쓸 생각인가

미팅, 노션 문서, 구글 워크스페이스 등등 파편화된 정보로 위키를 만들면 중앙에서 관리하는 효과를 볼 수 있을 것 같다. 중앙에서 관리하고 한 곳, 예를 들면 슬랙과 같은 하나의 툴에서 정리된 데이터를 한 번에 가져올 수 있다면, 분산된 데이터를 위해 여러 개의 툴을 스위칭하는 일이 적어질 것 같다는 생각이 들었다. 이 부분에서 불편함이 사라질 거라고 생각했다.

## 미심쩍은 대목

초기엔 다듬지 않은 생각들을 넣어두겠지만, 가공해서 정리된 내용들에 대해 단기기억과 장기기억을 구분해서 관리할 수 있을까? 만약 있다면 언제 어떻게 해야 될까? 한 번 저장된 데이터가 지속적으로 참조되지 않는 데이터라면 쓸모없는 데이터를 관리하고 있다는 생각이 들었다. 시간과 참조 횟수를 도입해서 정기적으로 중앙 관리된 데이터를 관리하는 게 좋겠다는 생각이 들었다. 구체적으로는 frontmatter에 조회수 필드를 두고 N ≤ M 같은 조건부를 걸어 관리하는 방식을 생각했다.
